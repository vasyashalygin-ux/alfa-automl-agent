# Alfa-Future AutoML Agent

Агент, который сам решает задачи табличного машинного обучения: читает `task.md`, исследует данные, подбирает модели и признаки, а на выходе создаёт `submission.csv`. Построен на LLM **Qwen3.8-27B** (через OpenAI-совместимый API) и цикле **AutoResearch**: LLM предлагает эксперименты, агент их запускает, проверяет на кросс-валидации и оставляет то, что улучшает метрику.

## Как это работает

1. **Разбор задачи.** Из `task.md` извлекаются файлы, ID-колонка, целевая переменная, метрика, формат ответа и положительный класс.
2. **Профилирование.** Анализ типов признаков, пропусков и распределений, adversarial validation (насколько test отличается от train).
3. **Валидация.** Выбирается схема: по времени с переобучением на всех данных, группы или стратификация.
4. **Признаки.** Частотные кодировки, статистики по строкам и группам, история объекта (out-of-fold, внутри фолдов, без утечки).
5. **Модели.** LightGBM, XGBoost, CatBoost и AutoGluon. Подбор гиперпараметров через Optuna.
6. **AutoResearch.** LLM-исследователь и эвристическая очередь предлагают эксперименты до истечения бюджета.
7. **Ансамбль.** Для регрессии: среднее лучших моделей (top-k). Для классификации: жадный подбор весов Caruana.
8. **Пороги классов.** Для меток (F1, precision, recall и т.п.) подбираются множители классов.
9. **Запись ответа.** Файл приводится к формату `sample_submission` и записывается атомарно.

Если LLM недоступна, агент работает на эвристиках. Ответ всегда пишется, даже при ошибке: сначала записывается константный ответ, потом улучшается.

## Поддерживаемые задачи

- **Регрессия:** RMSE, MAE, MSE, RMSLE, MAPE, MedAE, R², SMAPE
- **Классификация:** Macro/Weighted/Micro F1, F1, accuracy, balanced accuracy, MCC, kappa, ROC-AUC, PR-AUC, logloss, Brier, precision, recall
- Бинарные и многоклассовые задачи, строковые и числовые метки, несколько таргетов
- Формат ответа берётся из `sample_submission`: регистр названий колонок, ID, `class_*`-колонки

## Структура

Все файлы лежат в корне, как требует платформа:

| Файл | Назначение |
|---|---|
| `solution.py` | Точка входа: `python3 solution.py task.md` |
| `agent_config.py` | Настройки и таймер |
| `agent_task.py` | Разбор `task.md` |
| `agent_profiling.py`, `agent_validation.py` | Профилирование и схемы валидации |
| `agent_features.py`, `agent_entity.py` | Признаки и история объектов |
| `agent_models.py` | Обучение моделей и кросс-валидация |
| `agent_research.py` | Цикл AutoResearch и финальный ансамбль |
| `agent_llm.py`, `agent_prompts.py` | Клиент LLM и промпты |
| `agent_ensemble.py`, `agent_metrics.py` | Ансамбли и метрики |
| `agent_output.py`, `agent_writer.py` | Формат и запись `submission.csv` |
| `requirements.txt` | Зависимости |

## Запуск

```bash
pip install -r requirements.txt

export OPENAI_BASE_URL="<адрес API>"
export OPENAI_API_KEY="<ключ>"
# необязательно
export OPENAI_MODEL="qwen/qwen3.8-27b"
export AGENT_TIME_BUDGET=9600     # секунды, по умолчанию 2 ч 40 мин

python3 solution.py task.md
```

`submission.csv` появится рядом с `task.md`.

Ключ и адрес API **не хранятся в коде**: они читаются только из переменных окружения.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OPENAI_BASE_URL` | — | Адрес OpenAI-совместимого API |
| `OPENAI_API_KEY` | — | Ключ API |
| `OPENAI_MODEL` | `qwen/qwen3.8-27b` | Модель |
| `AGENT_TIME_BUDGET` | `9600` | Общий бюджет времени, секунды |
| `AGENT_N_JOBS` | по числу доступных CPU, не больше 8 | Потоки |
| `AGENT_NO_LLM` | `0` | `1` — работать без LLM |
| `AGENT_LLM_MAX_CALLS` | `40` | Лимит обращений к LLM |

## Ограничения

- Ресурсы по условиям: 8 CPU, 32 ГБ RAM, 3 часа на задачу.
- Без LLM агент использует только эвристики и обычно уступает полному запуску.
- Если API недоступен или закончился дневной лимит, агент продолжает работу без LLM.

## Тесты

В репозиторий не входят. Для локальной проверки используются синтетические задачи разных форматов и мок-сервер LLM.
